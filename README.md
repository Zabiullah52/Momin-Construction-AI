# Momin Construction AI

A Flutter + Firebase construction cost estimation, BOQ generation, and
project management platform for contractors, civil engineers, builders,
and homeowners.

## What's included in this starter

**Working Flutter code (real logic, not placeholders):**
- Full theme system (light/dark, construction-industry palette) — `lib/theme/`
- Auth: Signup, Login, Forgot Password, Google Sign-In — `lib/screens/auth/`
- Dashboard with feature grid — `lib/screens/dashboard/`
- **Construction Cost Estimator** with real engineering-ratio formulas
  (excavation, PCC, RCC, steel, brickwork, plaster, flooring, paint,
  electrical, plumbing) — `lib/services/calculation_service.dart`
- **BOQ Generator** with itemized quantities/rates/amounts — `lib/services/boq_service.dart`
- **Labour Cost Calculator** (productivity-based) and **Material Quantity
  Calculator** (mix-ratio based) — same service file
- **PDF and Excel export** for BOQs — `lib/services/export_service.dart`
- **AI Assistant** chat UI wired to a secure Cloud Function proxy
- **Saved Projects** (Firestore-backed CRUD)
- Editable, admin-controllable rate tables (`assets/rates/*.json` +
  Firestore `config/rates` + Cloud Function to update them)
- **Admin Panel** — dashboard KPIs, rate editor, user management (grant
  premium/admin), revenue view with charts, subscription plan config —
  `lib/screens/admin/`, gated by `AdminGate`
- **Subscription screen** — plan comparison table, Google Play/App Store
  billing via `in_app_purchase`, Stripe Checkout stub for Web —
  `lib/screens/subscription/`, `lib/services/billing_service.dart`
- **AI Design Module** — AI Floor Plan Generator (House/Plaza/School/
  Commercial templates, 2D image + algorithmic room dimensions + auto-BOQ),
  AI 3D Exterior Generator (Modern/Luxury/Classic/Islamic), Park/Mosque/
  Sports Complex Designers (concept image + BOQ), Download PNG, PDF design
  reports, and a Saved Designs gallery — `lib/screens/ai_design/`, backed
  by the `generateDesignImage` Cloud Function (OpenAI `gpt-image-1`,
  results stored in Firebase Storage + Firestore)
- **Account screen** (`lib/screens/account/account_screen.dart`) — sign
  out, plus in-app account + data deletion (required by Google Play's
  User Data policy for any app with account creation), wired to the
  `deleteAccount` Cloud Function

**Backend (Firebase):**
- `backend/functions/index.js` — `aiAssistant` (OpenAI text proxy with
  subscription-aware rate limiting), `generateDesignImage` (OpenAI
  `gpt-image-1` proxy for the AI Design Module), `resetMonthlyUsage`
  (scheduled), `verifyPurchaseAndActivate` + `stripeWebhook` (billing),
  `adminUpdateRates` (admin-only), `deleteAccount` (Play Store-required
  account/data deletion)
- `backend/firestore.rules`, `backend/storage.rules` — full security rules
- `analysis_options.yaml`, `.gitignore` — standard Flutter project hygiene files

**Documentation (`docs/`):**
- `ARCHITECTURE.md` — system design and rationale
- `DATABASE_SCHEMA.md` — every Firestore collection, field, and index
- `ADMIN_PANEL.md` — spec for the 5 admin screens (backend is implemented; UI is a build guide)
- `SUBSCRIPTION_SYSTEM.md` — free/premium limits, billing integration for Play/App Store/Stripe
- `AI_DESIGN_MODULE.md` — how AI image generation + room layout calculation works, and its limitations
- `DEPLOYMENT_GUIDE.md` — step-by-step Firebase setup → Play Store submission
- `NAVIGATION_FLOW.md` — full screen map

## What is NOT included (and why)

Being upfront: a handful of things can't be responsibly delivered as
static files in this format, and are documented instead so a developer
(or you, following the guide) can complete them:

1. **`firebase_options.dart` has placeholder keys.** Real values are
   generated by running `flutterfire configure` against *your* Firebase
   project — there's no way to pre-generate valid keys for a project that
   doesn't exist yet.
2. **Play Store submission** requires your developer account, signing key,
   screenshots, and store listing — a "ready build" in the literal sense
   needs a compiled `.aab` signed with *your* private key, which can only
   be produced by running the build guide on your machine/CI.
3. **Purchase verification is a scaffold, not a live integration.**
   `verifyPurchaseAndActivate` (Cloud Function) and the Stripe webhook are
   wired end-to-end structurally, but the actual Google Play Developer
   API / App Store Server API / Stripe signature-verification calls are
   marked `TODO` — you must create real products in Play Console/App Store
   Connect/Stripe first, then drop in those API calls (the exact spots are
   commented in `backend/functions/index.js`).
4. **AI-generated designs are concept art, not construction documents.**
   The floor plan/exterior/masterplan images are illustrative only — not
   to scale, not CAD-accurate, not building-code-checked. Room dimensions
   shown alongside the floor plan image come from a separate deterministic
   calculator, not from the image itself. See `docs/AI_DESIGN_MODULE.md`
   for the full explanation — this is also disclosed to the end user
   in-app on the AI Design Studio hub screen and in every exported PDF report.
5. **No Flutter/Android toolchain or network access exists in the
   environment that produced this code** (re-confirmed on request — every
   external host, including pub.dev and Google's servers, returns a hard
   403 allowlist block; no `flutter`/`dart`/`adb` binary exists), so
   `flutter pub get`, `flutter analyze`, building an actual `.apk`, and
   installing/testing on a device could not be run here. What *was* done
   as a substitute, and caught real bugs:
   - `node --check` on the Cloud Functions file (caught and fixed a broken
     comment block that would have failed to deploy)
   - A custom Dart tokenizer (correctly handling string interpolation,
     nested quotes, and comments) verified bracket/paren/brace balance
     across every `.dart` file — zero mismatches on the final pass
   - Every relative `import` statement was checked to resolve to a real
     file on disk — zero broken imports
   - Every cross-file constructor call (e.g. `FloorPlanInput(...)`,
     `DesignActionsRow(...)`) was manually diffed against its class
     definition to catch renamed/missing parameters
   - `pubspec.yaml` and `analysis_options.yaml` were parsed with a YAML
     parser to confirm they're syntactically valid
   - All JSON rate/config files were parsed with `json.load` to confirm
     they're valid

   This catches the large majority of what `flutter analyze` catches
   (unbalanced syntax, broken imports, wrong constructor args), but it is
   **not a substitute for actually running `flutter pub get && flutter
   analyze`** — package-API-level errors (e.g. a method that doesn't
   exist on a given package version, or a type mismatch the Dart analyzer
   would catch) can only be caught by the real Dart analyzer, since doing
   so requires the actual package sources from pub.dev. **Run `flutter
   analyze` yourself as the very first step after downloading** — see
   Quick Start below.
6. **The `android/`, `ios/`, and `web/` platform folders are not included
   on purpose.** These are large, mostly machine-generated folders
   (Gradle wrapper, `AndroidManifest.xml`, Xcode project files) whose
   exact contents depend on the Flutter/Gradle/Xcode versions on *your*
   machine — hand-writing them risks a stale Gradle wrapper JAR or a
   version mismatch that's harder to debug than just generating them
   correctly yourself. Run `flutter create .` in the project root as your
   literal first command (see Quick Start) — it fills in exactly these
   folders without touching `lib/`, `pubspec.yaml`'s dependencies, or your
   assets. (While preparing this project I also found and removed one
   genuinely invalid directory — a literal folder named `{models,screens`
   left over from an earlier shell brace-expansion mistake — so the `lib/`
   tree you have now is the cleaned-up version.)

## Quick start

```bash
flutter create . --platforms=android,ios,web --org com.momin --project-name momin_construction_ai
flutter pub get
flutter analyze          # run this first — see caveats #5 and #6 above
dart pub global activate flutterfire_cli
flutterfire configure --project=your-firebase-project-id
flutter run
```

To produce an actual installable, testable APK once the app runs clean locally:
```bash
flutter build apk --debug        # debug-signed, fine for sideloading/testing on a device
flutter install                  # installs it on a connected device/emulator
flutter build appbundle --release  # Play Store submission format — needs your signing key, see docs/DEPLOYMENT_GUIDE.md
```
If you don't have Flutter/Android set up locally, push this repo to
GitHub instead — `.github/workflows/flutter-ci.yml` automatically runs
`flutter clean`, `pub get`, `dart analyze`, `flutter analyze`, `flutter
test`, builds a release APK **and** AAB, and launches the app on a real
emulator to confirm it doesn't crash. Open the **Actions** tab after
pushing and download the APK/AAB/build-log from the finished run's
Artifacts section — see "Automated release signing in CI" in
`docs/DEPLOYMENT_GUIDE.md` if you want the pipeline to produce a
Play-Store-signed build rather than an unsigned one.

See `docs/DEPLOYMENT_GUIDE.md` for the full path to a production release,
including Firebase project setup, Play Store signing, and submission.
